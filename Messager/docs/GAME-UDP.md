# 0.3.22.0 独立 UDP 动作游戏通道

坦克动荡与羽毛球的新版连续输入和状态快照走独立 UDP 中继，端口 55221。聊天 TLS 服务仍监听 TCP 55220，登录、好友邀请、加入/离开房间和其他小游戏继续走原有可靠通道。两端在可靠游戏包中声明 UDP 能力，端点绑定与双向探测成功后才切换实时数据。旧客户端不声明能力，自动沿用 TLS。

本次按用户需求省略防作弊、签名、防伪造和独立 UDP 用户认证，没有修改登录密码哈希、聊天 TLS 或证书。UDP 中继只按用户名路由，不存账号、聊天或游戏数据。游戏碰撞、命中、比分仍由房主裁决，没有迁到服务器，也不宣称防作弊。

每个 UDP 报文最多 1200 字节，状态 JSON 压缩后发送；不能装入的包回退到 TLS，避免自行拆片。接收解压数据最大 32 KiB。快照只使用有效的新帧，输入沿用序号、回合、累计开火/跳跃/挥拍编号，持续发送可恢复个别丢包。旧快照不重传，房间控制消息保持可靠。

每 250 ms 绑定/探测一次；超过 900 ms 未收到对端回显或 1000 ms 未收到中继响应，实时包自动回退 TLS。双向探测恢复后自动切回。最差情况下通道故障检测期间可能短暂停顿，本地预测仍遵守上一版的 250 ms 安全停止。对局界面显示当前 UDP/TLS 通道；统计是对局回显耗时，不是纯网络 ping。

客户端仅在已登录状态绑定 UDP，登出或切换账号清空端点和对端能力。默认只为当前生产地址 8.160.172.25 启用 55221；其他部署可在 connection.json 中设置 gameUdpHost、gameUdpPort，端口 0 为关闭。地址需为 IP 字面量。

独立服务使用 tools/game_udp_relay.py（Python 标准库，无安装依赖），systemd 名为 cipherchat-game-udp。上线无需重启聊天服务或访问数据库。云安全组须放行入方向 UDP 55221；未放行时客户端自动保留 TLS。

验证记录在 work/udp-20261021：独立收发、重启恢复、超大/未知消息处理、会话清空、两款游戏实际 UDP 计数、文件并发、其余五款游戏回归、更新切换与回退。公网连通性以 public-udp-diagnosis.json / public-udp-probe.json 的实测结果为准，不以服务进程状态代替公网通过。

实现参考：[Qt 6.11 QUdpSocket 官方文档](https://doc.qt.io/qt-6.11/qudpsocket.html)。
