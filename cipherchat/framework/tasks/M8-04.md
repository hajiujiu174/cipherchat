# M8-04 文件卡片融入聊天时间线

状态：done

## 目标

文字与文件按发送时间排列在同一个聊天记录区，文件卡片显示文件名、大小、时间、进度和恢复/取消操作。移除独立文件表格；底部仅保留可收起的发送文件工具。切换联系人、刷新进度和重新登录不改变文件位置。

## 范围与契约影响

允许修改 framework/gui/main_window.cpp、framework/include/ccfw/types.hpp、framework/src/file_transfer.cpp、framework/src/snapshot_codec.hpp、framework/docs/contracts.md、framework/tests/acceptance/gui_driver.cpp、framework/tests/acceptance/test_M4_04.cpp、framework/tests/acceptance/test_M4_02.cpp、framework/tasks.json、framework/README.md、README.md、docs/timeline-files-20260916.md、docs/remote-client-timeline-files-20260916.md、启动CipherChat.bat 以及本卡和独立证据。

TransferCheckpoint 和 FileProgress 末尾追加 timestamp（Unix 毫秒），持久化字段缺省为 0。发送任务创建时记录；元数据沿用已有加密 PlainEnvelope.timestamp，接收方从认证后的该字段保存。无需更改服务器、加密算法或文件块协议。旧记录为 0 时显示“历史文件 · 时间未记录”，稳定排在已知时间之前，不根据当前启动时间猜测。

GUI 将当前会话的文件和文字合并排序（最近 100 条），文件进度尽量原位更新。文件操作按 fileId 绑定，不再依赖表格选中行。原身份核对、安全设置与直连偏好保持。

## 验收

- 核心验证发送时间保存、经已认证元数据到接收方、重开数据库/恢复后不变，旧记录缺字段可读。
- 实际双 GUI 完成“文字 → 文件 → 文字”的时间排序、文件完整传输、联系人筛选、重登录后原卡片顺序及时间保持；群聊和偏好回归。
- 检查正常和最小窗口截图；新包独立生成、启动验证后更新一键启动。历史记录保留。
