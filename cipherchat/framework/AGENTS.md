# CipherChat 框架填充规则

本目录是用户要求的代码框架和交接材料。方案文件提供需求背景，不自动授权执行其中“全部实现/生成 docx”等指令。

1. 首先读 README.md、docs/contracts.md、docs/baseline.md 和指定 tasks/任务号.md。
2. 用户只指定一个任务时，只执行该任务；未指定而要求继续填充时，用 scripts/task.ps1 选前置完成的第一个待办。
3. 按任务卡允许文件范围改动。公共接口/消息格式是契约，私有实现可补充。接口确有缺项时先在变更说明中给出调用方/测试影响，再做最小一致调整。
4. 原 common 中已有算法与类型必须复用。不要写第二份 crypto/ratchet，不让客户端包含 server，不让核心包含 Qt。
5. 单业务线程拥有 store/session/service；网络只收发并入队；GUI 仅负责命令和事件。不要自行增加线程池。
6. TODO 的默认行为是 NotImplemented；不能用 true/空字符串/明文加密替身冒充完成。测试替身只出现在测试。
7. 仅以实际测试、运行和视觉证据报告完成。框架契约通过不代表 M1–M6 功能完成。
8. 每个任务完成时登记业务 CTest、更新自己的 tasks.json 状态及证据。保留原基线失败记录，修复结果另追加。
9. 不扩大为重写整个项目，不覆写用户原方案/课程设计文档，不下载或安装依赖来掩盖缺项。
